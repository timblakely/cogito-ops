01Where it lives, and why that is the finding

The pi setup is not in home-ops at all. It is chezmoi-managed dotfiles — which means the client half of the LLM stack is version-controlled, reviewed, and rendered with the same rigor as the cluster half.

The repository's .chezmoiroot is home, so home/dot_pi/… renders to ~/.pi/… on every machine chezmoi manages. The source-of-truth map, from the repo's own README:

SourceDestinationWhat it is
dot_pi/agent/models.json.tmpl~/.pi/agent/models.jsonTwo providers, both litellm.jory.dev: jory-litellm (openai-completions, 18 models) and jory-litellm-anthropic (anthropic-messages, MiniMax + auto). The API key is rendered by a chezmoi onepasswordRead template — the same LITELLM_OPENCODE_API_KEY the opencode pod uses
dot_pi/agent/agents/*.md~/.pi/agent/agents/The five role agents — markdown with YAML frontmatter pinning tools and model per role
dot_pi/agent/extensions/~/.pi/agent/extensions/subagent (the child-process launcher), workflow (the durable runner, new this week), statusbar, context-report
dot_pi/agent/workflows/*.json~/.pi/agent/workflows/Three portable workflow definitions — §4
dot_pi/agent/prompts/ · settings.json · mcp.json.tmpl~/.pi/agent/…Coordinator system prompt, defaults (reasoning-pool, compaction at 16k reserve / 20k recent), ToolHive MCP via pi-mcp-adapter with lifecycle: lazy
dot_local/bin/executable_pi-*~/.local/bin/pi-child · pi-leanLauncher scripts for delegated children and a minimal-context variant

Two machine-local files are deliberately excluded via .chezmoiignore — auth.json and models-store.json — so chezmoi apply reconciles configuration without ever clobbering runtime state. Secrets never touch the repo: chezmoi renders them from 1Password at apply time, and the README records the validation that was done (an unauthenticated GET to the ToolHive gateway returned 401; the redacted rendered config loaded through pi 0.84.2 and adapter 2.27.0 before the change shipped).

The structural irony worth noticing

The same seventy-two hours that produced this config also deleted the alias layer from the LiteLLM proxy (Routing Teardown §12) — proxy model names are now deployment names. The stable-name indirection did not die; it migrated here. explorer, fixer, and friends are role names in harness config, and when the week's economics forced two backend retargets (§2), the role names absorbed both without a single caller changing. The alias layer is load-bearing wherever it lives; Jory moved it, cogito keeps it in the proxy — but somebody has to hold it.

02The role market

Five agents, and the load-bearing insight: roles are not just capability tiers, they are price points — and the coordinator is told the prices.

AgentModelContextPrice seatJob
explorer mimo-v2.5 go plan 256k Cheapest by a wide margin ($0.14/$0.28) Read-only recon; fan out several in parallel — "this is how you buy context." Explicitly the weakest reasoner: locating and summarising, never judgement
fixer llama-nvidia local 140k Free, but contended by Foreman Fast scoped edits (54s p95 — the fastest lane he has) and the only image-capable lane: Qwen 3.8-27B on the 3090 with the vision projector encoding on CPU
fixer-bigctx dsv4f go plan 1M Mid-priced, own $15/mo sub-cap Primary bulk coding lane; parallel implementation attempts; falls back to GPT-5.6 Luna when its cap is spent. Never fast: 117s p95
oracle dsv4p go plan 1M Most expensive; use deliberately Hard debugging, root-cause, architecture. Read-mostly — "return a recommendation, don't sprawl into edits"
reviewer MiniMax-M3 anthropic-messages 1M — Independent review — deliberately a different model family from the Qwen coders and DeepSeek analysts

The prompt is an economics briefing

The coordinator system prompt does three unusual things. First, it carries the price model verbatim — "the Opencode Go plan is metered in DOLLARS, not flat-rate… prefer several explorer passes over one speculative oracle call." Second, it specifies a delegation contract: every brief must carry the objective, the decisions already settled with exact values inlined, the files the sub owns, what is out of scope, and the observable check that proves success — "a sub should never have to infer scope or re-derive a decision you already made." Third, it institutionalises the council: high-stakes review gets independent verdicts from different model families — DeepSeek, MiniMax, Qwen — reconciled by the coordinator. "Never let one model grade its own work."

Why the prices are in the prompt: they moved twice in a week

The Go plan was believed flat-rate; it is actually dollar-denominated — $60/month, $30/week, $12 per rolling five hours. On 2026-08-16 dsv4f was repriced roughly 8× (to $0.22/$0.66) and handed its own $15/month sub-cap inside the $60. The response was two lane retargets in two days: explorer moved from dsv4f to mimo-v2.5, and fixer-bigctx moved from the retired qwen3.7-plus onto dsv4f. Both were one-line model swaps behind stable role names — the churn the role layer exists to absorb, demonstrated live. The honest caveat travels with it: the coordinator's cost model is prose in a prompt, so it drifts the moment the provider reprices again, which is exactly what the chezmoi diff history is for.

03Subagents are processes, not threads

Delegation spawns a separate pi process per child, which is what makes the isolation, the caps, and the abort story simple.

  • Isolated context by construction. Each child gets its own context window, the delegated system prompt, and the role's tool whitelist. A child whose frontmatter omits model inherits the dispatching session's model and thinking level.
  • Bounded fan-out. Parallel mode caps at 8 tasks, 4 concurrent; each completed task returns at most 50KB to the parent model, with full output retained in tool details. The launcher consumes pi's message_end JSON events plus stderr — the README notes it deliberately does not depend on an unsupported tool_result_end event, a scar from an earlier version that did.
  • Abort propagates. Ctrl+C kills the child processes; a child that dies before producing output returns its stderr as diagnostics rather than vanishing.
  • The trust boundary is explicit. Only user-level agents (~/.pi/agent/agents) load by default. Project-local agents (.pi/agents/*.md) are repo-controlled prompts that can run bash — they require agentScope: "both" to load at all, and untrusted projects get an interactive confirmation on top.
  • Agents are discovered fresh per invocation, so a role definition can be edited mid-session and the next delegation picks it up.

Three prompt presets wrap common chains — /implement (scout → planner → worker), /scout-and-plan, /implement-and-review. Those are one-shot templates; what shipped this week is their durable successor.

04The workflow layer

Merged 2026-08-21: an opt-in runner that turns delegation chains into declarative, resumable state machines. Definitions are portable JSON in chezmoi; run state is machine-local and crash-safe.

Workflows are discovered from ~/.pi/agent/workflows/*.json and driven by /workflow list · show · start · status · pause · resume · quit. Four stage types compose them: delegate (single or bounded-parallel, to the named role agents), check (deterministic command), approval (human gate), and repair-loop (bounded retry). Handoffs between stages are explicit — handoffFrom names exactly which prior outputs enter a task — and size-capped; full outputs survive only where a stage declares an artifact. Run state lives in state.json written via same-directory temp file, fsync, and rename, so an interrupted write can never replace the last good state.

The other two shipped workflows exercise the remaining shapes. debug-until-green is oracle-diagnose then a repair loop bounded at two attempts, and its README note is characteristically careful: the free-form input is diagnosis context only — it is never executed, because the check is the fixed trusted git-diff-check. review-pr is the council as a workflow: resolve the PR target, then a parallel fan-out of three read-only lanes — explorer, oracle, reviewer, three model families — synthesized by the reviewer into a saved review.md artifact.

05Foreman's rails, miniaturised

Every safety idea in the workflow layer has a named ancestor in the batch pipeline. This is Foreman's philosophy — model output is evidence, not authority — carried into interactive work.

RailIn Foreman (batch)In the workflow layer (interactive)
verdicts grounded Reviewer must quote the ask verbatim and anchor findings to changed lines; unverified GO demotes to NO-GO failureIfContains: "ACTIONABLE FINDINGS" makes the verdict machine-checkable, and deterministic check stages run regardless of what any model claims
no shell from models Gate commands come from a per-repo profile in git, digest-pinned check stages resolve only a name in the extension's trusted registry of fixed argvs — no command arrays, no shell strings, no {input} expansion into commands, ever. Adding a check means adding a fixed argv to source first
bounded retries maxTurns 160/80; three attempts then escalate; then BLOCKED Repair loops must declare maxAttempts and the extension hard-caps them at 3; parallel delegation caps at 4 children
human at the gate A human appears exactly once — at merge mutation: true stages require interactive approval; an approval stage can pre-approve named mutation stages — and resume revokes prior approvals, so a resumed run always re-confirms before touching the tree
honest blast radius Coders run rootless in Jobs; verify is the repo's own CI Stated in the README rather than implied: "the runner has no sandbox: use a disposable worktree or container for autonomous mutation"

The pattern underneath all five rows: the model proposes, the harness disposes. The workflow definition is data a model could plausibly have written; the registry, the caps, and the approval semantics live in the extension's code, which a workflow cannot override. That division — definitions portable and cheap, enforcement centralised and versioned — is the part worth copying even where the specific rails differ.

06One brain, three harnesses

The same roles, keys, tools, and memory span pi, opencode, and Zed — and one of the three now also runs as a pod.

  • opencode grew a body in the cluster. An opencode serve pod with a kopiur-backed 20Gi home, home-ops pre-cloned at boot, committing as the Saffron bot, fronted by authentik SSO — a coordinator that survives the laptop's lid. Its agent config carries the same coordinator-plus-five-roles as pi's.
  • Zed shows the constraint the others escape. It has exactly one global subagent model, so it cannot fan out to a cheap lane the way explorer does — the config pins it to nvidia as the fastest lane and the comment tells the operator to keep Zed subagent jobs bounded. A harness's delegation model limits which economics you can express.
  • Auth converged the hard way. ToolHive gained API-key auth this week; all three clients now send the same 1Password-backed x-api-key, with chezmoi rendering the key because Zed uses header values verbatim and cannot expand env vars.
  • The two-source wrinkle. The pod's opencode config is a home-ops ConfigMap that mirrors the dotfiles template by hand. It has already been patched pod-side three times in two days (server working directory, envsubst escaping, memini plugin) — a drift surface the memory namespace makes worth watching, since both ends write to it.

07What cogito lifts, and what it does not

Cogito already runs pi — the pi virtual key and the llm-proxy-refresh extension exist today — so most of this section is one chezmoi PR, not a project.

Lift

  • The workflow layer, near-verbatim. Portable JSON definitions plus one extension, already engineered for exactly cogito's shape of work. The one adaptation worth making on day one: extend the trusted check registry with gitops-shaped fixed argvs — kustomize build over the rendered path, git diff --check — so "the worker says it updated the YAML" gets the deterministic verification the Routing Teardown's §11 already demands.
  • A price-aware coordinator prompt, inverted. Jory's capacity policy rations dollar lanes; cogito's shape is the mirror image — worker and reviewer seats are free and plentiful (six seats after the retune in The Idle Bench §2), so the prompt should say fan out locally by default, and escalation to GLM 5.3 / K3 is entered on failure, with per-key budgets as the hard backstop.
  • The delegation contract paragraph. Objective, settled decisions inlined, files owned, out-of-scope, observable success check — this is the discipline that makes short self-contained worker prompts (the whole cache argument) actually short and self-contained.
  • The council, across cogito's families. Local Qwen, GLM 5.3, and K3 are three families; review-pr's fan-out-then-synthesize shape maps onto them directly, and it is a workflow definition, not infrastructure.

Do not lift

  • Roles only in the harness. Jory deleted his proxy aliases and pays for it in coupled renames; cogito's role aliases stay in LiteLLM because multiple clients (Open WebUI, Hermes, pi) and per-key spend attribution consume them there. Harness role names on top of proxy aliases is the right stack for this cluster — two thin layers, each absorbing its own kind of churn.
  • The dollar-lane arithmetic. Cogito's lanes are free-local plus two subscriptions; the useful residue is the principle (tell the coordinator the ladder), not the numbers.
  • Mutation without a sandbox. The README's own warning stands: autonomous mutation stages belong in a disposable worktree. Cogito's jj-colocated repos make that cheap — take the advice literally.

The cluster-side seating these roles call into — which provider sits behind coordinator, worker-escalated, reviewer-escalated, and the retrieval floor — remains The Idle Bench §6; nothing here changes it. What this document adds is the missing client half: the coordinator pattern is not a proxy feature, and the seventy-two hours that built it twice at Jory's are the proof it lives in the harness.
